# チーム開発の進め方

このプロジェクトは、Issue を「1人が1〜2日で完了でき、遊べる変化として確認できる単位」に分けて進めます。

## 開発の流れ

1. GitHub Issue で目的と完了条件を確認する
2. `feature/<issue番号>-短い名前` のブランチを作る
3. その Issue に関係する変更だけを実装する
4. Unity で実行して動作を確認する
5. Pull Request を作成し、スクリーンショットか短い動画を添える
6. レビュー後に `main` へ取り込んで Issue を閉じる

## 最初の担当分け

| 領域 | 最初の成果 | 依存関係 |
| --- | --- | --- |
| コア操作 | 球を狙って投げ、ピンと衝突できる | なし |
| スコア | 2投制・ストライク・スペアを表示できる | コア操作 |
| 演出/UI | 投球の手応え、効果音、リザルト画面 | コア操作 |
| 公開 | WebGL ビルドを第三者が遊べる形で出す | 最低限のゲーム完成 |
| 品質 | 操作・得点・リセットの確認項目を整える | 各機能 |

## PR の最小チェック

- 関連 Issue を本文で `Closes #番号` として結ぶ
- Unity Console に新しいエラーがない
- 操作方法を README に反映する（変わった場合）
- 画面の変化がある場合は画像か短い動画を添える
